# M0-08 Spike: text proxy behavior — INCOMPLETE (blocked, no measurements)

Status: **no measurements were obtained.** Every item below is NOT TESTED. Do not copy anything from this file into
ROADMAP §5 as a fact; only the blocker and the recipe are useful.

## Question

Across available hosts: `documentContextBeforeInput/AfterInput` lengths, behavior at paragraph boundaries,
`adjustTextPosition` units (UTF-16 vs grapheme) with emoji / combining marks / Devanagari, `selectedText` updates,
marked text.

## Method (what was built)

A throwaway probe keyboard (not committed) replaced the stub: buttons ran scripted sequences through
`textDocumentProxy` (synthetic strings only: `ab` + U+1F600, flag U+1F1EE U+1F1F3, ZWJ family, `e`+U+0301,
Devanagari U+0928 U+092E U+0938 U+094D U+0924 U+0947, thumbs-up + skin tone; 3000-char run; 3 x 40-char paragraphs).
After each step it displayed only counts (UTF-16 length, grapheme count of before/after context, `selectedText`
length, `hasText`, last/first 3 scalar values, `selectionDidChange`/`textDidChange` counters) in a label read back via
`axe describe-ui`. It built and installed fine on a fresh iPhone 12 / iOS 27.0 simulator (`xcrun simctl create`,
because `simctl clone` of the booted base sim fails with "Unable to clone device in current state: Booted").

## Blocker (observed facts)

1. Host load: `uptime` load averages were 450-1000 for the whole session (5 spike simulators booted plus
   builds). First boot of the sim froze Safari (stale frame, clock not advancing, `axe` "Timed out creating the
   simulator remote automation session"); after a reboot `axe describe-ui` worked.
2. `simctl openurl data:...` fails (LSApplicationWorkspaceErrorDomain 115). An http page served from
   `python3 -m http.server` on 127.0.0.1 loads in Safari (use `--bind 127.0.0.1`; `localhost` timed out).
3. After the page loaded, `axe tap` on the textarea, the Safari address bar and the Tabs button all reported success
   but produced no visible effect; `axe type` produced no text. Replacing the host with an own SwiftUI
   `TextField` + `TextEditor` and tapping by accessibility id also gave no focus and **no soft keyboard**
   (screenshots in `M0-08-assets/`). `defaults read com.apple.iphonesimulator ConnectHardwareKeyboard` is 0 but
   `Simulator.app` is not present/running (headless), so the likely cause is the sim treating a hardware keyboard as
   attached, or taps not delivered under load. Not isolated further. `defaults write com.apple.UIKit
   GSEventHardwareKeyboardAttached -bool NO` did not help.
4. Consequently the iBoard keyboard could never be shown, so no probe ran.

## Conclusions

None about proxy behavior. Recommend re-running this spike (a) with machine load low (one simulator at a time) and
(b) after establishing a working way to show the soft keyboard on a headless sim (try `Simulator.app` with
I/O > Keyboard > "Connect Hardware Keyboard" off, or run on the physical iPhone together with M0-03).

## Impact on ROADMAP

No decision or risk changed. R-10 (`adjustTextPosition` units differ by host) and the M2/M5 dependency on M0-08
remain open; M5-02 and cursor-offset logic must still assume grapheme-vs-UTF-16 is unknown.

## Facts suitable for ROADMAP §5 (tooling only)

- `xcrun simctl clone` cannot clone a booted device; use `simctl create <name> <devicetype> <runtime>` instead.
- `simctl openurl` rejects `data:` URLs; serve test pages over http on 127.0.0.1.
- Under heavy host load (>400 load average) simulator UI automation via `axe` is unreliable (timeouts, ignored taps).
