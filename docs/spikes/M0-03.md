# M0-03 — Extension memory ceiling

**Device:** owner's iPhone 12 (iPhone13,2), iOS 27.0 (24A437), debug build, Full Access off, 2026-10-26.

**Method:** throwaway probe in the keyboard extension allocated and dirtied 5 MB every 0.25 s, writing
`phys_footprint` (task_vm_info) to a file in the extension's own container before each step. After the extension was
killed, the next launch displayed the last value.

**Result:** the last recorded step was **76 MB footprint (70 MB of probe blocks + ~6 MB baseline)**. The next step
(~81 MB) did not survive, so the jetsam limit is in **[76, 81) MB**. No `didReceiveMemoryWarning` fired before the kill
(the file would have said WARNING). Idle baseline of an empty keyboard: ~5 MB.

**Caveats:** single run, one device, one iOS build, foreground host app unknown; the limit may vary with host-app memory
pressure and across devices. The simulator does not enforce this limit (not tested). Probe code was not committed.

**Impact:** ceiling ≈ 76–80 MB, well above the 50 MB threshold in ROADMAP §6, so the 30 MB target / 40 MB hard cap stay
unchanged (the hard cap leaves ~2× headroom). No memory warning precedes the kill, so budgets must be enforced by us.
