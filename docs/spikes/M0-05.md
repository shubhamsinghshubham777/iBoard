# M0-05 Spike: Full Access matrix (simulator)

Date: 2026-10-26. Simulator: fresh iPhone 12, iOS 27.0 runtime (clone of the shared sim was refused because it was booted). Build: Debug, ad-hoc simulator signing, App Group `group.app.iBoard`.

## Question
With `RequestsOpenAccess` false vs true (and, for true, "Allow Full Access" switched on in Settings), what works in the keyboard extension: App Group `UserDefaults`, group-container files, Darwin notifications, haptics, `playInputClick`, pasteboard, network?

## Method
- Throwaway probe (`Probe.swift`, same file in app and extension, not committed). Every 3 s each process wrote to App Group defaults (`probe.<role>`) and to a file in the group container, read the other process's value, posted a Darwin notification and counted the other's, and (extension only) called `UIImpactFeedbackGenerator`/`UISelectionFeedbackGenerator`, `UIDevice.playInputClick()` (with `UIInputViewAudioFeedback`), wrote/read `UIPasteboard.general`, and sent `HEAD https://example.com`. Results were written to each process's own container and read with the shell. No typed text was read or logged.
- Run 1: `RequestsOpenAccess=false`. Run 2: `RequestsOpenAccess=true`, then Settings > Apps > iBoard > Keyboards > Allow Full Access ON (confirmed `hasFullAccess == true` in the extension).
- The app hosted a text field so app and extension were alive at the same time (needed for cross-process Darwin delivery).
- Raw outputs: `docs/spikes/M0-05-assets/*.json`; screenshots `openaccess-false-keyboard.jpg`, `openaccess-true-keyboard.jpg`.

## Results (extension unless noted)

| Capability | RequestsOpenAccess=false (`hasFullAccess` false) | true + Allow Full Access (`hasFullAccess` true) |
|---|---|---|
| `hasFullAccess` | false | true |
| App Group `UserDefaults` write + read back | OK | OK |
| App Group `UserDefaults` read of value written by the app | OK ("w-app") | OK |
| App reads value written by extension | OK | OK |
| Group-container file write | OK | OK |
| Group-container file read of app's file / app reads ext's | OK both ways | OK both ways |
| Darwin notification ext to app and app to ext (counted) | OK (ext saw 4, app saw 3) | OK (ext 5, app 6) |
| `UIImpactFeedbackGenerator` / selection generator | no error; feel NOT TESTED | no error; feel NOT TESTED |
| `playInputClick` | no error; audio NOT TESTED | no error; audio NOT TESTED |
| Pasteboard write then read back | OK (`hasStrings` true) | OK |
| Network (`HEAD https://example.com`) | HTTP 200 | HTTP 200 |

## Conclusion
**The iOS Simulator does not enforce the Open Access sandbox.** Every capability that Apple documents as requiring Full Access (shared container, network, pasteboard, haptics) worked with `hasFullAccess == false`. This run therefore proves only that: (a) the code paths work and are error-free with Full Access on, (b) `hasFullAccess` correctly reflects the Settings toggle in the simulator, (c) the Settings toggle and the keyboard-enable flow can be driven with `axe`. It does NOT prove what works without Full Access on a real device.

NOT TESTED (needs a real iPhone, owner device; belongs with M0-03/M0-09): behaviour of every row with Full Access OFF, real haptic feel and latency, input-click audio, pasteboard prompt, Darwin delivery to a suspended app. Until then, treat Apple's documented behaviour as authoritative: without Full Access the extension cannot reach the App Group container (writes and reads fail or are silently empty), has no network, and haptics/pasteboard are restricted.

## Impact on ROADMAP
- P-06 (exact read rules to M0-05): still unresolved for real devices; sim cannot settle it. Keep the extension-local-storage design (D/R-03 fallback) as mandatory, do not assume group reads without Full Access.
- R-03 (App Group not readable without Full Access): NOT retired. Keep the in-keyboard essential-settings fallback (ROADMAP line ~258).
- M3-01, M9-03, M6: must stay gated on `hasFullAccess` at runtime; do not use the simulator as proof of non-Full-Access behaviour.
- No locked decision in section 4 is contradicted.

## Facts for ROADMAP section 5 (copy)
- iOS 27.0 simulator: Open Access is not enforced. With `hasFullAccess == false` the extension still read/wrote App Group defaults and files, used the network (HTTP 200), pasteboard and haptic/click APIs without errors. Only `hasFullAccess` itself changes. Real-device matrix remains NOT TESTED.
- `hasFullAccess` flips to true after Settings > Apps > iBoard > Keyboards > Allow Full Access (confirm dialog) and the keyboard being re-shown; requires `RequestsOpenAccess=true` in the extension Info.plist.
- Darwin notifications (`CFNotificationCenterGetDarwinNotifyCenter`) are delivered between a foreground app and the extension both ways in the simulator.
- Simulator keyboard enabling: `defaults write -g AppleKeyboards -array "en_US@sw=QWERTY;hw=Automatic" "app.iBoard.keyboard"` alone was not enough on a fresh sim; it worked after also setting `AppleKeyboardsExpanded -bool true`, rebooting, tapping into a text field, and pressing the globe key (system keyboard is the default; the globe cycles to iBoard). iBoard then appears under Settings > Apps > iBoard > Keyboards.
- Automation tips: `axe tap` can time out ("remote automation session") while the host is overloaded (load averages in the hundreds with 5+ sims booted); retry. `simctl bootstatus` and `simctl spawn` can hang under the same load. Cloning a booted sim fails (code 405); use `simctl create` with the same device type and runtime instead.
