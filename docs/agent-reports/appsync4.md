# appsync4 — app-side sync key wiring (M12)

## Changed (app target only)
- `iBoard/ThemeStudioView.swift`: the Sendable `PhotosPicker` label no longer reads `model`; the title is computed outside the closure. Both strict-concurrency warnings are gone.
- `iBoard/SyncKeychainItem.swift` (new): production `SyncKeychain`. One synchronizable generic-password item (`kSecAttrSynchronizable` true, `AfterFirstUnlock`), update-then-add, errors carry only the OSStatus. No logging.
- `iBoard/SyncSettingsView.swift`: `SyncSettingsModel` now uses `SyncKeyManager`. The old auto-created key (`Keychain.syncKey()`) is removed. The model takes injectable store, keychain, defaults, memory file and personal store.
  - Enable: if iCloud has shards and there is no key, the state is `keyMissing` and nothing is uploaded or created.
  - `SyncOutcome.keyMismatch` becomes `keyMismatch` state, and the merged result is not saved.
  - UI: "Encryption key missing/mismatch" section in plain words, with Check again and "I lost the key: start over" (confirmation dialog, destructive).
  - `startOver()`: erases unreadable iCloud data, makes a new key, re-syncs.
  - Delete iCloud data: still confirmed, and now reports failure honestly.
- `iBoardTests/SyncSettingsModelTests.swift` (new, fake keychain + in-memory store): key created when the cloud is empty; key missing is not auto-created; mismatch is surfaced and startOver recovers; delete turns sync off and keeps the key.
- `scripts/audit-privacy.allowlist`: WRITE entry for `SyncKeychainItem.swift` (key material only, app only).
- `iBoard.xcodeproj` regenerated by xcodegen (gitignored or not, per repo convention).

## Verified
- `scripts/build.sh`: BUILD SUCCEEDED, no Swift warnings. The one remaining build warning is a project config issue, not code: extension CFBundleShortVersionString '1.0' vs app '1.0.0' (project.yml, outside my ownership).
- `scripts/test.sh --no-ui`: TEST SUCCEEDED, including the 4 new tests.
